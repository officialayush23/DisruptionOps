# 3D icon prompts — DisruptionOps deck

Everything in the deck that can carry a graphic, as a matched 3D icon set.

**How to use this.** The STYLE BLOCK is the whole trick. An icon set fails when
each icon is generated with its own wording and comes back at a different camera
angle, light direction and level of detail — so they never sit together on a
slide. Paste the style block **unchanged** before every subject line, generate
them all in one session so the tool carries its own consistency, and change
nothing between runs except the SUBJECT.

**Never ask a 3D generator for text or labels.** Rendered lettering comes back
garbled or misspelled every time. Icons carry no words; the words go in
PowerPoint next to them.

---

## THE STYLE BLOCK — paste before every subject

```
Single 3D icon, soft-clay / matte-plastic render, centred on a fully
transparent background. Isometric three-quarter view from slightly above,
camera at roughly 30 degrees. Soft studio key light from the top-left, gentle
ambient fill, one soft contact shadow directly beneath the object. Rounded,
friendly geometry with generous fillets on every edge — no sharp corners.
Matte surfaces, very slight subsurface softness, no gloss, no chrome, no
reflections, no rim light.

Palette, and nothing outside it:
  deep navy      #11253C   — primary bodies, housings, the mass of the object
  slate blue     #3D5468   — secondary surfaces
  muted blue     #6E8194   — small parts, hinges, trim
  terracotta     #B23A24   — one accent only, on the single most important part
  teal           #2E7D8F   — second accent, used sparingly
  off-white      #F3F6F9   — screens, paper, highlights

Composition: one object, centred, filling about 80% of a square frame, with
clear breathing room at the edges. Simplified and iconic rather than
mechanically accurate — readable at 100px. No text, no letters, no numbers,
no logos, no watermark, no UI chrome, no ground plane, no background scenery,
no gradient backdrop, no sparkles or glow effects, no human figures.

Square 1:1, 2048×2048, transparent PNG.

SUBJECT:
```

## The two composite scenes

Not icons. These are small illustrated scenes in the same material language, and
they need a wider frame.

### Scene 1 — the allocation problem (slide 02)

```
[STYLE BLOCK, but change the last two lines to:]
Wide 16:9 frame, 2560×1440, transparent background.
Several objects arranged as a small scene rather than a single centred icon.

SUBJECT:
A small isometric city district in soft clay, five separate trouble spots
marked by five map pins of different colours scattered across it. In one
corner, well away from the pins, a single small cluster of parked vehicles —
noticeably too few for five pins. No lines drawn between them, no arrows.
The composition should read as: five places need help, and there is one
small pool of units. Leave clear empty space between the vehicle cluster and
the pins.
```

### Scene 2 — manual coordination vs DisruptionOps (slide 03)

```
[STYLE BLOCK, but change the last two lines to:]
Wide 16:9 frame, 2560×1440, transparent background.
A two-part composition, left half and right half, clearly separated.

SUBJECT:
LEFT HALF — a tangle of old desk telephones connected by curling, knotted
cables that cross over each other and lead nowhere. Two identical rescue
boats pointing at the same single map pin while two other pins nearby have
nothing heading toward them. Cables and duplicated boats in terracotta.
Muddled, congested, overlapping.

RIGHT HALF — the same five map pins, each with exactly one matched vehicle
travelling toward it along a clean single curved path. One path visibly bends
around a small barrier. A slim vertical stack of neat ledger cards beside the
scene. Ordered, spaced, calm. Paths and ledger in teal.

The contrast between the two halves is the entire subject: knotted and
duplicated on the left, resolved and singular on the right. No text, no
labels, no dividing line drawn between the halves — the spacing does it.
```

## Getting a consistent set

**Generate in one continuous session.** Most tools carry style within a thread
and lose it between them. If the tool exposes a seed, fix it and vary only the
subject.

**Do the ten-icon set first, in order.** By icon three the tool has settled into
the material; if icon one looks different afterwards, regenerate it last so it
matches the nine that followed.

**Reject early.** If an icon comes back glossy, or lit from the right, or with a
ground plane, discard it rather than keeping it — one mismatched icon in a grid
of ten is more visible than a missing one.

**Check the accent discipline.** Terracotta should appear once per icon, on the
part that matters. An icon where three parts are terracotta will shout across
the slide at everything beside it.

**Knock out the background if it comes back white.** A white square on a white
card is invisible until the card is tinted, and then it is a grey box. Confirm
real transparency before placing.

## One caution, and it is the same one as before

These are raster images. They cannot be edited later, they do not know when the
system changes underneath them, and their text — if any survives — cannot be
corrected. That is exactly how the old architecture image ended up still showing
mesh reporting weeks after mesh was deleted from the code.

3D icons are safe in a way that generated *diagrams* are not: an icon carries no
claim. A boat is a boat next year. So use them freely as decoration beside real
labels, and keep the structural diagrams — the bands, the timelines, the
comparison matrix — as native shapes where a wrong word can be fixed in ten
seconds the night before judging.
